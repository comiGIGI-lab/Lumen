# HTTPS 安全连接实操指引（含踩坑记录）

> 场景：给部署好的站点配一个 `https://` 开头的地址。
> 本文是 2026-09-24 在阿里云 ECS 上实际配通一遍后的总结，**目标读者是"下次的 AI"** ——
> 照着判断、照着敲，不要再把已经证伪的路重走一遍。
>
> 本次环境：阿里云 ECS · Ubuntu 24.04.5 · nginx 1.24 · 公网 IP `47.106.76.244` · **无备案域名**

---

## 0. 先判断：走哪条路线（30 秒）

**按顺序问这三个问题，答案直接决定路线：**

| # | 问题 | 是 → | 否 → |
|---|---|---|---|
| 1 | 服务器在**中国大陆**吗？（阿里云/腾讯云大陆地域、华为云大陆…） | 继续问 2 | **路线 A**（境外机器不受备案约束，`sslip.io` / Let's Encrypt 随便用） |
| 2 | 有**已备案**的域名吗？ | **路线 B**（标准做法，最省事） | 继续问 3 |
| 3 | 只要能演示用的**临时**地址，还是要**长期稳定**的？ | 临时 → **路线 C**；稳定 → **路线 D** | |

**一句话结论：**
- **大陆 + 无备案域名** = 所有"免费造域名"的玩法（sslip.io / nip.io / xip.io）**全部不可用**，
  原因见 §2 的实测证据。**唯一免费可行的是 Cloudflare 隧道（路线 C）。**
- 想要稳定的 `https://`，最终都得回到「**一个域名**」上（路线 B 或 D）。

---

## 路线 A：服务器在境外 —— 最简单
境外机器没有备案拦截，随便一个域名 + Let's Encrypt 即可：

```bash
# 1. 域名 A 记录指向服务器 IP（sslip.io 这种通配 DNS 也能用）
# 2. 装 certbot 并签发
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your.domain.com        # 自动改 nginx、自动续期
```
`sslip.io` 玩法：`IP 的点换成横线` + `.sslip.io`，例如 `1-2-3-4.sslip.io` → `1.2.3.4`。
**只要服务器不在大陆，这条路又免费又好用。**

---

## 路线 B：大陆 + 已备案域名 —— 标准做法
```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your.filed-domain.com  # HTTP-01 验证会自动通过
```
备案是这个路线的**前提**：大陆机房对未备案域名会在 80/443 做拦截（§2）。

---

## 路线 C：大陆 + 无备案 + 要临时地址 —— Cloudflare 隧道（本次采用）

**原理**：服务器上的 `cloudflared` **主动向外**连 Cloudflare 边缘，
**没有"入站域名流量"给运营商检查** → 绕开备案；
并且拿到的是 **Cloudflare 签发的受信任证书**（不是自签，浏览器不报警告）。

### 执行步骤
```bash
# 1) 装 cloudflared —— ★ 千万不要从 GitHub release 直连下载（国内实测 ~21KB/s，39MB 必超时）
#    走 Cloudflare 官方 apt 源，秒装：
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list >/dev/null
sudo apt update && sudo apt install -y cloudflared

# 2) 起隧道，指向本机 nginx 的 80（前端与 /api 走同一域名，不跨域）
cloudflared tunnel --no-autoupdate --url http://localhost:80
# 日志里会出现一行：https://<随机三个词>.trycloudflare.com  ← 就是它

# 3) 做成常驻服务（否则关了终端就断）
sudo tee /etc/systemd/system/cloudflared-quick.service >/dev/null <<'EOF'
[Unit]
Description=Cloudflare Quick Tunnel -> nginx
After=network-online.target nginx.service
Wants=network-online.target

[Service]
Type=simple
User=admin
ExecStart=/usr/local/bin/cloudflared tunnel --no-autoupdate --url http://localhost:80
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=cloudflared-quick

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now cloudflared-quick.service

# 4) 取当前地址（★ 写个小脚本，因为地址会变）
journalctl -u cloudflared-quick.service --no-pager -n 500 \
  | grep -oE 'https://[a-z0-9-]+\.trycloudflare\.com' | tail -1
```

### ⚠️ 必须知道的限制
- **地址是随机的，每次重启都会换** → 演示当天别重启；查地址用上面第 4 步
- 免费匿名隧道**没有可用性保证**（Cloudflare 官方原话）
- 想要**永久固定**地址 → 路线 D

---

## 路线 D：大陆 + 要稳定地址 —— 自有域名 + Cloudflare 命名隧道
需要一个**域名**（几十块/年，**不需要备案**）+ 免费 Cloudflare 账号：
```bash
cloudflared tunnel login                 # 浏览器授权
cloudflared tunnel create study-liu
cloudflared tunnel route dns study-liu study.your-domain.com
cloudflared tunnel run study-liu         # 配合 systemd 常驻
```
域名托管在 Cloudflare 上 → 隧道走 Cloudflare 边缘 → **不触发大陆备案拦截**，且地址固定。

---

## 路线 E（兜底）：只用 IP
`http://<IP>` **任何情况下都能用，最稳**，缺点是没有小绿锁、地址不好看。
本次的备用地址就是 `http://47.106.76.244`。

## §2 ★ 为什么 sslip.io 在大陆不可用（实测证据，别重走）

网上那篇讲 sslip.io 的文章本身没错，但它**默认服务器在境外**。大陆机房多了 ICP 备案这一层。

实测：`47-106-76-244.sslip.io` 的 **DNS 解析完全正常**（→ `47.106.76.244`），但：

| 访问方式 | 结果 | 判读 |
|---|---|---|
| `http://…sslip.io/`（80） | **HTTP 403，页面标题 `Non-compliance ICP Filing`** | 被注入阿里云备案拦截页 |
| `http://…sslip.io:3000/` | **同样是备案拦截页** | ★ 换个端口也没用 |
| `https://…sslip.io/`（443） | **TLS 握手被直接打断**（0.06s 就失败） | 按 **SNI 域名**掐断 |
| `https://<IP>/`（SNI 不带域名） | **HTTP 200 正常** | 这组对照证明拦的是"域名" |
| `http://<IP>:8080` 等 | 超时 | 安全组没放行，与备案无关 |

**结论：拦的是「未备案域名」本身**，与用哪家通配 DNS、用哪个端口都无关。
→ 因此 **Let's Encrypt 的两条验证路都被堵**：
  - HTTP-01 要走 80 → 被备案页拦
  - TLS-ALPN-01 要走 443 + 真实 SNI → 被掐断
→ **自建受信任证书也做不到**（只能自签，浏览器照样警告）

### 诊断命令（照抄）
```bash
U=http://47-106-76-244.sslip.io
curl -s -o /dev/null -w "HTTP %{http_code}\n" $U/            # 403
curl -s $U/ | grep -o "<title>[^<]*</title>"                  # Non-compliance ICP Filing → 就是它
curl -sk -o /dev/null -w "%{http_code}\n" https://47-106-76-244.sslip.io/   # 000 = 握手被打断
curl -sk -o /dev/null -w "%{http_code}\n" https://<IP>/       # 200 = 不带域名就没事（对照）
```
**只要看到 `Non-compliance ICP Filing`，就不用再折腾域名了 —— 备案是硬门槛。**

## §3 踩坑记录（都是真踩过的）

1. **大二进制别从 GitHub 直连下载**
   本次 `cloudflared`（39MB）从 GitHub release 下，**实测 ~21KB/s，180 秒只下了 3.8MB 就超时**。
   更糟的是我的脚本只判断"文件非空"就把**截断的半个二进制**装进了 `/usr/local/bin` ✗
   → **正确做法**：(a) 走厂商自己的 apt/yum 源；(b) **下载完必须校验大小或哈希**，
   不能只判断文件存在。

2. **先确认安全组/防火墙放行了哪些端口**
   本次实测 443 是通的（连接被拒绝 = 端口开着但没服务），而 8080/8888/9000 是超时（没放行）。
   → 判断方法：`curl -m 8` 看是**迅速被拒绝**（端口通）还是**超时**（没放行）。

3. **改 nginx 前必备份 + `nginx -t` 校验 + 失败回滚**
   ```bash
   sudo cp -a /etc/nginx/sites-available/default /path/backup/
   sudo sed -i 's/.../.../' /etc/nginx/sites-available/default
   sudo nginx -t && sudo systemctl reload nginx || cp -a /path/backup/default /etc/nginx/sites-available/default
   ```

4. **隧道地址会变** —— 别把地址硬编码进 PPT，或者演示当天别重启服务。

5. **别把"看到页面"当成"验证通过"**
   本次浏览器自动化遇到一个坑：导航明明报错，随后的页面快照却**完整显示了目标页面** ——
   那其实是浏览器里**已加载的旧标签页**。→ **必须用 `location.href` 复核当前 URL。**
   （另：这台机器上**明文 HTTP + 裸 IP 会被拦，HTTPS + 域名正常** ——
   所以给站点配好 HTTPS 之后，浏览器自动化反而也能用了。）

## §4 配好之后的验收清单
```bash
U=https://<你的地址>
curl -s -o /dev/null -w "首页 %{http_code}\n" $U/
curl -s $U/ | grep -o "<title>[^<]*</title>"          # 标题对不对
curl -s -o /dev/null -w "接口 %{http_code}\n" $U/api/health
curl -sI $U/ | grep -iE "^HTTP|server:|cf-ray"        # 证书/边缘节点
# 浏览器打开，地址栏应无安全警告（Cloudflare 隧道是受信任证书）
```

## §5 回滚方法
```bash
sudo systemctl disable --now cloudflared-quick.service   # 停隧道
sudo rm -f /etc/systemd/system/cloudflared-quick.service
sudo systemctl daemon-reload
# nginx 若被 certbot 改过：用备份覆盖回去 + nginx -t + reload
# 站点本身不受影响，http://<IP> 始终可用
```
