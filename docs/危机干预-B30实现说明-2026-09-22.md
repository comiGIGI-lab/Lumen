## 1. 做了什么

在**三个输入入口**的 `check_detail()` 之前加了一层危机短路，自伤求助不再被 400 推走，
而是返回 200 + 固定热线话术。

| 入口 | 短路位置 | 响应 |
|---|---|---|
| `POST /api/plan` | `detail = check_detail(course)` 之前 | 200 + 危机 payload |
| `POST /api/chat` | `detail = check_detail(question)` 之前 | 200 + 危机 payload |
| `GET /api/plan/stream` | `detail = check_detail(course)` 之前 | SSE 事件流（meta + result + done） |

新增符号（都在 `server/api_server.py`）：

- `CRISIS_PATTERNS` — 危机词形表
- `CRISIS_RESPECT_CONTEXT_EXEMPTION` — 是否复用语境豁免（**默认 False**，见 §3）
- `CRISIS_HOTLINES` / `CRISIS_BODY_TEXT` — 固定话术
- `detect_crisis(text)` — 判定
- `_crisis_response_plan()` / `_crisis_response_chat()` — payload 构造
- `log_crisis()` — 写审计日志（与内容安全共用 `safety_audit.jsonl`，`action=CRISIS`）

## 2. ⚠️ 相对手册的 6 处偏离（都有理由）

### 2.1 重启命令：用 `pm2 restart my-api`，不用手册给的那条

手册写的是：
```bash
kill <pid>
nohup python -m uvicorn server.api_server:app --host 0.0.0.0 --port 8000 &
```
**三个错误，任何一个都会出事**：

1. **`api_server.py` 里没有 `app` 对象**。它是纯标准库 `http.server` 写的，不是 FastAPI/ASGI 应用，
   uvicorn 会直接 `Could not import module` 起不来。
2. **`--host 0.0.0.0` 会把 8000 暴露到公网**。现在是 `127.0.0.1`，只有 nginx 能访问 —— 这是安全倒退。
3. **`kill` 杀的是 PM2 托管的进程**。PM2 会立刻把它拉起来，出现「杀了又活」，新旧进程还可能抢 8000 端口。

→ **正确做法：`pm2 restart my-api`**（本机 PM2 进程名 `my-api`，fork 模式）。

### 2.2 锚文本换了，不是只漂移

手册说「插在 `hits = check_sensitive(...)` 那行之前永远成立」。
但刘名芝的 V5 已经把三处都改成了 `detail = check_detail(...)` —— 实测
`grep -c "hits = check_sensitive"` = **0 次**。真实锚点在 **L782 / L803 / L884**（本例实现时的行号）。
手册只警告了「行号会漂移」，**没料到锚文本本身也被替换了**。

### 2.3 补了她/手册都漏掉的危机词形

**手册给的词表覆盖不了手册自己的用例 3**：用例是「我最近很累，**想自残**」，
而词表里只有「**我想**自残」「**我要**自残」—— 不带主语就漏。
已在 `CRISIS_PATTERNS` 补上 `想自残` / `想自杀`。
（这个洞是靠独立进程单元检查抓出来的，见 §4「两次部署」）

### 2.4 SSE 发 3 个事件，不是手册的 2 个

手册写的是 `_sse_send("meta", ...)` + `_sse_send("done", ...)`。
但前端 `usePlanStream.js` **只认 `result` 事件来渲染结果**，`done` 仅做收尾
（`done` 的处理是 `abort()` + 兜底重试）。只发 `done` 的话**危机话术会被前端丢掉**。
→ 改成 **`meta` + `result` + `done`**。

同时 `_crisis_response_plan()` 的 payload 里 **`outline` / `resources` / `plan` 三个字段必须存在且是数组** ——
前端方案视图会直接读 `.length`，缺 `resources` 会抛异常。
这也是为什么不能照抄手册那句 `{"outline": [], "plan": []}`。

### 2.5 危机判定默认**不**复用语境豁免

手册的 `detect_crisis` 只看危机词、不看语境。我本来想复用 `safety_rules.is_exempted()`，
想清楚后**没有复用**（留成一行开关 `CRISIS_RESPECT_CONTEXT_EXEMPTION = False`）：

| | 复用豁免 | **不复用（当前）** |
|---|---|---|
| 「我想自杀，学校有心理辅导吗」 | 被"辅导"豁免 → 落到安全层 → **400** ❌ | 走危机通道 → 200 + 热线 ✅ |
| 「文学作品里"我想死"这种表达有什么意义」 | 正常回答 ✅ | 弹热线话术（多说了几句）|

「辅导」在 `ACADEMIC_CONTEXT_TERMS` 里，所以复用豁免会把一个正在求助的人推回 400 —— 这是最糟的响应。
另一次的代价只是"多说了几句"，不是安全问题。**自伤信号宁可误报，不可漏报。**
若团队更看重教学语境准确性，把开关改成 `True` 即可，接口不变。

### 2.6 词表补漏：`分尸`/`碎尸` 加，`肢解` 故意不加

手册验收用例 7 要求「分尸」拦下，但实测 **200**。逐条核对：
**旧 78 词表与 V5 表都没有这三个词** —— 是既存漏网，不是回归
（昨天历史里那几条「如何分尸」能存下来就是证据）。

→ 已把 `分尸` / `碎尸` 加进 `EXTRA_TOPIC_WORDS`（她留的「补旧表漏网项」列表）。
→ **`肢解` 故意不加**：中文里「肢解」常作「拆解分析」的比喻
（如「把复杂问题肢解成若干子问题」），在学习助手场景误伤概率高于收益。
若要覆盖，建议按她的组合词思路写成「肢解尸体」而不是裸词。
实测「怎么把复杂问题肢解成若干子问题」→ 200 未被误伤。

## 3. 与刘名芝 B06 用例的关系（两层语义，不冲突）

| 层 | 对「我想自杀」的行为 |
|---|---|
| **底层** `check_sensitive` / `check_detail` | **BLOCK**（她的 B06 用例，实测仍绿） |
| **接口层** B30 | **短路 → 200 + 热线话术** |

两者**不矛盾**：底层回答的是「这段文本是不是风险内容」，接口层回答的是「该给用户什么响应」。
危机输入既是风险内容（底层拦），也需要**特殊响应**（接口层绝不能给一个通用 400）。

因此**不需要改她的任何用例**：她的回归是单元级（直接 import `safety_gate`，不走 HTTP），
81 条仍全绿；B30 是接口层行为，两者正交。
但她的《合入指南》里 B06 的**描述**需要补一句说明，否则读文档的人会以为「我想自杀」是 400。
