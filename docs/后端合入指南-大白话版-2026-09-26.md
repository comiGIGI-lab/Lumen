## 一、后端一共管哪几件事（一句话版）

后端就是藏在页面后面的那个 Python 进程，它管四件事：

| 编号 | 干什么 | 代码在哪 | 一句话说明 |
|---|---|---|---|
| 1 | **内容安全** | `server/safety_words.py` `safety_rules.py` `safety_gate.py` | 危险提问拦下来，正常学习提问必须放过去 |
| 2 | **危机响应** | `server/crisis.py` | 发现自伤求助 → 直接给两条**写死在代码里**的心理热线 |
| 3 | **错误文案** | `server/error_text.py` | 出错时不把系统报错甩给用户，只说人话 |
| 4 | **业务接口** | `server/api_server.py` | 生成学习方案、课程问答、知识库、错题本… |

**评委可能问的点**：第 1 和第 2 件事的方向是**相反**的 ——
内容安全宁可漏拦不可误拦（教育场景不能被误伤）；危机响应宁可多给一张卡片不可漏掉一个人。

## 二、改了后端，怎么让它生效（三步，别漏第三步）

```bash
# ① 把代码推到 Gitee / 或直接在服务器上拉
ssh admin@47.106.76.244
cd /home/admin/ai-coding
git pull --ff-only origin master

# ② 重启后端进程（关键！漏了这步 = 白改）
pm2 restart my-api

# ③ 看它活着没
pm2 list | grep my-api      # 状态应该是 online
curl -s http://127.0.0.1:8000/api/health   # 期望 {"ok": true}
```

> ⚠️ **最容易踩的坑**：Python 进程是**常驻内存**的，`git pull` 只改了磁盘上的文件，
> **不重启就还在跑旧代码**。踩过两次：
> ① 前端改了只 pull 不 build → 页面不变；
> ② 后端改了只 build 不 restart → 页面变了但**新接口 404**。
>
> ⚠️ 前端改动是**另一套流程**（要在服务器上 `cd web && npm run build`），别混。

## 四、出问题怎么退回去（回滚）

后端出问题一般是**某次提交引入的**，退法：

```bash
cd /home/admin/ai-coding
git log --oneline -5                 # 找到上个好用的提交号，比如 505a0f0
git reset --hard <那个提交号>         # ⚠️ 只在应急时用，会让工作区回到那个状态
pm2 restart my-api
curl -s http://127.0.0.1:8000/api/health
```

只想**临时关掉危机响应**（不想动 git）：
把 `server/api_server.py` 里三处 `if detect_crisis(...)` 的调用注释掉，然后 `pm2 restart my-api`。
（不推荐长期这样，只用于排查。）

**网页白屏了**怎么办：那是前端的事，看 `docs/DEPLOY.md`；备份在
`/home/admin/backups/dist-pre-2026xxxx`，还原就是 `cp -a` 回去。

## 六、被问到时的标准回答（可以直接背）

**Q：为什么热线号码不直接让大模型写？**
> 因为我们实测过：让模型自由回答时它会**编**出一个号码（400-161-9995），机构名还挂错了。
> 在教学/安全场景里，给错的求救号码比不给更严重。所以凡是「学生会照着做」的东西——
> URL、热线号码——我们一律做成**代码常量**，不交给模型。

**Q：为什么危机响应不给用户一点"安慰话"，只发固定卡片？**
> 危机时刻不赌大模型即兴发挥。而且这条路径是**短路**的：命中后四条 Agent 一步不动，
> 零 token、零等待，耗时约 20 毫秒 —— 现场打开日志抽屉就能看到。

**Q：老师问「如何识别学生轻生倾向」会不会被当成危机？**
> 不会。危机词表配了两级**教育语境豁免**：一句话里出现「识别 / 学生 / 干预」这类词就放行。
> 我们专门把「如何识别学生轻生倾向并干预」写进回归用例，每次改动都要跑一遍。

**Q：为什么不用现成的第三方库（比如敏感词库）？**
> 服务器只有 1.6G 内存，每多一个依赖就多一次装不上的风险。我们全部用标准库实现，
> 一共 4 个文件，评委可以逐行看。
