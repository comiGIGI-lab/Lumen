## 2. 决策点详解（PPT 每点一页）

### D1 · SSE 而非 WebSocket
- **选型**：Agent 串行推进，单向推送刚好匹配；自带降级通道。
- **备选**：WebSocket 全双工（对本场景过重）。
- **缺陷**：无（已含 `POST /api/plan` 降级兜底）。
- **PPT 亮点**：链路可逐节点点亮，是 3 分钟里最能抓住评委的前几秒。

### D2 · 纯标准库 `http.server` 而非 FastAPI
- **选型**：git clone 即跑、2C2G 机器无负担。
- **代价**：路由、校验、依赖注入全部手写。
- **缺陷**：未实现 `do_PATCH`/`do_DELETE`，RESTful 形态受限（当前场景用不到）。
- **PPT 亮点**：「clone 即跑、零依赖」是硬资产。

### D3 · Vue3 + Vite，原型静态挂 `public`
- **选型**：正式链路 Vue3 `<script setup>` + Vite 6（依赖树仅 `vue`/`vite`/`@vitejs/plugin-vue` 三个包）；未接通后端的新页面以纯静态 HTML 放 `web/public/prototypes/`，与 Vue 应用互不相干、共用端口不跨域。
- **代价**：两套设计令牌并存漂移。
- **缺陷（待修复）**：改名后命名体系未对齐（产品名「智识有方」 vs 种子/KEY 仍 `study-liu`，localStorage key `zjxt.welcomed` 残旧）；`4253662` 去紫（AppHeader 重写 288 行）+ `global.css` 令牌合并（106 行）已进一步收敛令牌漂移。
- **本次迭代变化**：`1664136` 多模态定位进首屏 + 产品改名「智识有方」；`4253662` 去紫 + 场景/悬浮组件进仓（不影响核心选型）。
- **PPT 亮点**：设计可在零后端下独立迭代到 v0.4；接口契约直接把原型假数据映射成真实字段名，对接有据可依。

### D4 · `X-Client-Id` 而非账号系统
- **选型**：按浏览器隔离历史，一个自定义请求头换掉整套注册登录，边界正好停在「单机演示」。
- **代价**：无跨设备同步（演示态选择，与 D6 同源）。
- **缺陷（待修复）**：`Access-Control-Allow-Headers` 未放行该头，跨域部署必挂（`api_server.py:764`）；**同域部署不受影响**。
- **PPT 应答**：CORS 只在分域部署时才是钉子，当前同域无碍。

### D5 · 本地四层判定引擎而非内容安全 API
- **选型**：复合词组 → 拼音层 → 意图句式 → 议题词 + 语境豁免。
- **代价**：词形枚举式维护，新说法需人工补。
- **缺陷**：无（V5 落码包清零：误伤 7/7 → 0/33，ASCII 死词 → 词表与输入统一 lower；晚间补至 84 用例覆盖分尸/碎尸/肢解，0 误伤 0 漏网；纯标准库，三层可独立降级）。
- **PPT 亮点**：本地、离线、零外部 API 调用，安全是硬资产。

### D6 · JSON 文件而非数据库
- **选型**：单人演示场景，绝对路径 reviewer 看得见，出问题 `cat` 一下就知道。
- **代价**：无事务、无跨设备同步、无备份恢复。
- **缺陷（待修复）**：`client_history.json` 读改写无锁，并发会丢写（演示单用户无碍）。

### D7 · 关键词平铺而非向量 / BM25
- **选型**：2C2G 约束下唯一不会拖垮机器、也不需要 2GB 依赖的方案。
- **缺陷（未实现）**：无分词、无排序、无分页（当前数据量无碍）。

### D8 · LLM 兼容层零依赖自研而非 LangChain / LiteLLM
- **选型**：144 行换对五家 OpenAI 兼容平台的无差别支持，换厂商不用动代码；失败显式化 + 降级可观测（trace 落因 + 环境变量可调）。`requests` 为唯一硬依赖。
- **缺陷（留观）**：对外仍静默降级，LLM 不可用时界面不报错（演示翻车点）。

### D9 · AES-GCM + PBKDF2 密钥加密而非明文
- **选型**：Key 落盘即密文，上层拿到的永远是明文，支持旧配置自动迁移。
- **缺陷（待修复）**：无 `cryptography` 库时退化为可复原的 base64。

### D10 · 危机干预短路返回 200 + 热线
- **选型**：危机判定优先于内容安全层，固定话术不经过大模型，热线全部可核验。
- **缺陷**：无（词形枚举式维护，新说法需人工补）。

## 3. 演示闭环（赛期必跑通的一条线）

**画像 → 生成 → 问答 → 导出**

- **画像**：`WelcomeScreen.vue` 多模态定位首屏，由 `App.vue` 的 `shouldShowWelcome()` 控制（首访 localStorage 无 `zjxt.welcomed` 弹，深链不弹）。
- **生成**：`POST /api/plan` 生成课件 / 笔记。
- **问答**：SSE 流式答疑，命中可溯源。
- **导出**：`ExportPreview` 已接 `api`，Markdown + 浏览器打印 PDF 可演示。
- **导入（轻量闭环）**：粘贴即笔记——后端 `paste_import(text)` 不经过 HTTP / multipart，避开 nginx 256k 限制，是演示里最省事的导入路径。

## 4. 评委可能追问的应答（三句式）

- **实时方案**：SSE 而非 WebSocket，单向推送匹配 Agent 串行语义，自带降级通道。
- **安全**：本地四层判定 84 用例 0 误伤 0 漏网，纯标准库、三层可独立降级。
- **可运行**：纯标准库后端 clone 即跑，2C2G 无负担、零额外依赖。
- **设计先行**：Vue 组件化 + 静态原型双轨并行，令牌漂移已列修复项（合并令牌而非重写）。
- **隔离**：`X-Client-Id` 换掉整套账号系统，边界停在单机演示。
