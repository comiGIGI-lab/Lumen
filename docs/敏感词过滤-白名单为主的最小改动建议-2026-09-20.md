## 1. 为什么提这件事

`378fe4c` 把词库从 30 词扩到 78 词，方向是对的，但只扩词库、不动匹配逻辑，结果是「该拦的拦得更全，不该拦的也拦得更全」。78 词实测下来，正当教学提问的拦截面反而比 30 词时更大。

对一个教学助手来说，最不能接受的是把保护学生的提问掐死 —— 「如何识别学生的轻生倾向并做危机干预」被拒答，在演示现场比此前的「黑客攻击」案例杀伤力大得多。这件事建议在演示之前处理掉。

## 2. 现状（实测）

匹配逻辑在第 275–280 行，是纯子串匹配：

```python
def check_sensitive(text: str) -> list:
    """返回文本中命中的敏感词列表（不区分大小写）。"""
    if not text:
        return []
    low = text.lower()
    return [w for w in SENSITIVE_WORDS if w in low]
```

调用点三处：`POST /api/plan`（课程名，第 791 行）、`POST /api/chat`（提问，第 813 行）、SSE 链路（第 894 行）。

两个附带发现。其一，`low` 只转输入、不转词库，所以 ASCII 敏感词「DDoS」在任何输入下都命中不了（`"DDoS" in "ddos攻击教程"` 恒为 False），这条词目前是死的。其二，`SENSITIVE_WORDS` 实测 78 词，单字「枪」确已移除，「杀人」「作弊」「轻生」「自残」「钓鱼网站」「弹药」「军火」均在列。

---

## 3. 先说清楚：全词匹配救不了这批用例

原方案提的是「全词匹配 + 白名单」。实测之后要更正：**对这批中文用例，全词匹配基本无效，能救场的是白名单。**

原因是中文没有空格分隔，`\b` 分词不可靠。更关键的是，这批用例里敏感词本来就是连续词素 —— 「故意杀人罪」里的「杀人」是一个完整语素，「杀人手法」里的「杀人」也是，全词匹配照样命中，因为它本来就是「全词」。

还有一个 `re` 的坑：Python 的 `\w` 在 str 模式下匹配 CJK，所以 `\bddos\b` 在「DDoS攻击教程」里匹配失败（「s」和「攻」之间没有边界）。若要用正则做 ASCII 全词匹配，得写成「前后不为 ASCII 字母/数字」的断言，不能用 `\b`。

所以全词匹配只保留给 ASCII 词（DDoS 这类），中文用例一律交给白名单。逐用例的结论见下表。

## 5. 建议改法：白名单为主，全词匹配只留给 ASCII 词

思路是给 `check_sensitive` 加两层豁免，命中就放行或豁免该词，其余维持原逻辑不动。改动集中在两个新增常量 + 函数体替换，`SENSITIVE_WORDS` 一行不动。

第一层是整句短语白名单：出现「故意杀人罪」「防作弊」「危机干预」这类完整短语，说明是明确的教学语境，整句直接放行。

第二层是按敏感词的窗口上下文豁免：取命中词前后各 12 个字符，窗口内若出现「防范」「构成要件」「干预」「战争」这类安全上下文词，就把该词从命中列表里去掉，其余词照常生效。这样既能放行「故意杀人罪的构成要件」，又不会因为一句话里出现「考试」就把「买答案」也一起放掉。

### 参考实现

在 `SENSITIVE_WORDS` 定义之后新增两个常量：

```python
# 豁免短语：整句出现时视为合法教学语境，整句放行
EXEMPT_PHRASES = [
    "故意杀人罪", "过失致人死亡", "杀人未遂", "杀人手法", "杀人案", "杀人案件",
    "防作弊", "反作弊", "学术诚信", "考试诚信",
    "危机干预", "自杀干预", "轻生倾向", "自残干预", "心理危机", "自杀预防",
    "钓鱼网站识别", "防范钓鱼", "反钓鱼",
    "弹药补给", "军火采购", "武器演进",
]

# 安全上下文：命中敏感词的邻近窗口内出现这些词，说明是防护/学科讨论意图
SAFE_CONTEXT = [
    "防范", "防御", "识别", "检测", "预防", "干预", "治疗", "疏导", "成因",
    "构成要件", "罪名", "刑法", "犯罪构成", "案例分析", "叙事结构",
    "战争", "军事", "演进", "补给", "采购", "后勤",
    "学术诚信", "监考", "教学设计",
    "心理", "危机", "咨询", "辅导",
]

# ASCII 敏感词改用「前后不为 ASCII 字母/数字」的断言做全词匹配。
# 注意不能用 \b：Python re 下 CJK 也算 \w，"DDoS攻击" 里 s 与"攻"之间没有边界。
_ASCII_RE = {
    w: re.compile(r"(?<![a-zA-Z0-9])" + re.escape(w.lower()) + r"(?![a-zA-Z0-9])")
    for w in SENSITIVE_WORDS if w.isascii() and w.isalnum()
}

_WINDOW = 12
```

函数体替换为：

```python
def check_sensitive(text: str) -> list:
    """返回文本中命中的敏感词列表（不区分大小写）。

    两阶段：先按整句豁免短语放行，再按敏感词的邻近上下文豁免，
    最后才落回子串匹配。目的是避免"防作弊方案""危机干预"这类
    正当教学提问被误拦。
    """
    if not text:
        return []
    low = text.lower()

    # 1) 整句出现豁免短语 -> 直接放行
    for p in EXEMPT_PHRASES:
        if p in low:
            return []

    # 2) 收集命中词：ASCII 走全词匹配，中文仍走子串
    hits = []
    for w in SENSITIVE_WORDS:
        if w in _ASCII_RE:
            if _ASCII_RE[w].search(low):
                hits.append(w)
        elif w in low:
            hits.append(w)

    # 3) 邻近窗口内出现安全上下文 -> 豁免该词（不影响其它命中词）
    kept = []
    for w in hits:
        i = low.find(w.lower())
        window = low[max(0, i - _WINDOW): i + len(w) + _WINDOW]
        if any(c in window for c in SAFE_CONTEXT):
            continue
        kept.append(w)
    return kept
```

顶部需补 `import re`（源文件是否已 import 需后端确认，若已有则不用加）。

## 7. 几条给后端的提醒

`SAFE_CONTEXT` 是这套方案里唯一需要谨慎调的地方。上下文词选得太宽会放跑真违规内容（比如放「考试」进去，「买考试答案」就会被豁免），选得太窄又救不回来。上面的版本已经把「考试」从上下文里剔掉，改由短语白名单「防作弊」「学术诚信」兜底，就是为了避开这个坑。后续加词时建议按同一原则：优先加短语白名单，其次才动上下文。

`EXEMPT_PHRASES` 建议随演示用例同步维护。演示前把要讲的几个课程名和问题过一遍，命中就补进白名单，比事后在现场翻车划算。

演示环境如果允许，更稳妥的做法是给过滤加一个开关（比如 `/api/settings` 里的 `sensitive_filter_enabled`），演示时开、平时开，但把白名单调宽。这样即使漏网也有兜底。这条不是必须，看排期。
