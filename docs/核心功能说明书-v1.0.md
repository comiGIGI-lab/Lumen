## 1. 学习方案生成

> Hero 卡片原文：输入课程名，选好水平和每日时长。系统给出课程大纲、推荐资源和可以勾选的每日计划。

### 1.1 需求

**要解决的问题。** 学生想学一门新课，第一步往往是「不知道从哪开始、不知道要多久、不知道看什么资料」。通用大模型能给一份泛泛的建议，但它不知道用户的水平、每天能投入多少时间、什么时候要考。

**需求定义（FR-09 / FR-06）。** 输入课程名与结构化画像，输出「课程大纲 + 推荐资源 + 学习计划」三栏结果，并把 Planner → Searcher → Writer → Reviewer 的执行过程实时可视化。

**画像字段**（`web/src/components/CourseForm.vue`）：课程名、当前水平、每日可投入时长、学习目标（期末 / 考研）、截止日期。这五个字段是方案生成的唯一输入面。

> **形态变更说明（FR-06）**：原始需求描述为「预设 Prompt 模板，用户填空」。实现形态改为结构化表单——可枚举字段比自由填空更利于后端稳定生成，也便于缓存命中判断。此项与原需求文字存在差异，在答辩口径中需主动说明。

**验收标准。**

1. SSE 推流，四个节点依次点亮，且每个节点显示**真实产出数量**（如 `10 章` / `4 条` / `21 天` / `质检通过`）。
2. 推荐资源链接由**程序按标题生成**（视频 → B 站、书籍 → 豆瓣、其它 → MOOC），模型给的链接一律丢弃，防止幻觉链接。
3. 大纲每个章节带 **≥3 条具体要点**；Reviewer 校验每章至少 2 条非空要点，不达标自动重跑一轮。
4. 截止日期真正影响计划天数：剩余天数被夹在 `[5, 30]`；无截止日则按总可用时长分档（7 / 14 / 30 天）。
5. 改动数据结构时必须同步升级缓存版本号，否则 24 小时内旧缓存继续返回旧结构，表现为「改了没用」。

### 1.2 技术方案

**链路。** 意图识别 → **Planner**（拆章节）→ **Searcher**（找资源）→ **Writer**（排计划）→ **Reviewer**（校验）。业务层位于 `vendor/study-liu/`，与桌面版**同一份代码**，Web 后端只做包装，不存在两套会漂移的实现。

**后端落点。**

| 落点 | 作用 |
|---|---|
| `GET /api/plan/stream` | ★ SSE 主链路，推 `meta / trace / step / result / error / done` 六类事件 |
| `POST /api/plan/stream` | SSE 的 POST 变体 |
| `stream_pipeline()` | 把 `run_plan_pipeline` 的产出转成事件流 |
| `POST /api/plan` | 非流式降级通道（SSE 连不上时前端自动回落） |
| `POST /api/export` | 导出 Markdown / Word |
| `POST /api/cache/clear` | 清空结果缓存 |

**为什么链路要可见。** 后端把 `agent_loop` 写出的 `data/trace.log` 实时转成 SSE 事件流，前端 `TraceDrawer.vue` 还能回放原始轨迹。「一条链路」的价值就在于看得见推进过程——这也是四段式 Agent 从黑盒变白盒的关键。

**为什么用 SSE 而非 WebSocket。** Agent 是串行推进的，单向推送正好匹配其语义；浏览器原生 `EventSource` 自动处理断流重连，比 WebSocket 少一半代码。

**Mock / LLM 双模式。** Mock 模式不调用任何在线接口（Planner 走课程分类模板、Searcher 走内置资源库、Writer 走活动模板），**离线可跑、演示零风险**；LLM 模式调用 DeepSeek / OpenAI / Qwen / GLM / Kimi，失败自动降级并在界面顶部弹出橙色告警说明「本次方案并非大模型生成」。

**前端落点。**

| 文件 | 作用 |
|---|---|
| `CourseForm.vue` | 课程名 + 画像输入 |
| `usePlanStream.js` | ★ SSE 状态机 |
| `PipelineStepper.vue` | 流水线实时状态条 |
| `ResultsGrid.vue` / `ResultPanel.vue` / `PlanPanel.vue` | 三栏结果渲染 |
| `ExportPreview.vue` | 导出预览（Markdown / 打印 PDF / Word） |
| `HistoryDialog.vue` / `usePlanHistory.js` | 历史方案回看与回填 |

### 1.3 界面与交互

1. 首访进入欢迎层，点「开始使用」进入主界面。
2. 在「📖 想学什么课程？」填课程名（或点快捷课程按钮）。
3. 选用户画像（可选但推荐）：水平 / 每日时长 / 目标 / 截止日期。
4. 点「✨ 生成方案」（或直接回车）。
5. 观察状态条：`🧭 Planner → 🔎 Searcher → 📝 Writer → ✅ Reviewer`，每节点变绿带出真实产出数量；若 Reviewer 判定不达标，会看到 Writer / Searcher 回环重跑。
6. 三栏结果填充：课程大纲（章节 + 要点）、推荐资源（类型 + 链接）、学习计划（Day 1…N，可勾选）。
7. 后续动作：`📥 导出方案` / `📜 日志` / `💬 课程问答` / `🕘 历史`。

**视觉**：沿用全站设计令牌——米底 `#FBF9F6`、衬线刊名、强调色 `#E51520`、胶囊按钮；暗色模式下 25 个组件 93 处硬编码颜色已变量化，并做了防闪白处理。

## 2. 知识库

> Hero 卡片原文：笔记、导入的资料、语音转写和思维导图都收在这里。之后的提问和闯关先从这些内容里找依据。

### 2.1 需求

**要解决的问题。** 学生的资料散落在课件 PDF、课堂录音、图片板书和零散笔记里，既无法统一检索，也无法让 AI 基于「我自己的材料」来答疑。通用大模型脱离课程材料作答，容易出现看起来合理但与该课程无关的编造。

**需求定义（FR-01 / FR-02 / FR-15）。**

- **FR-01 自定义 RAG 知识库**：上传课件、PDF、图片等资料建立个人知识库，问答仅基于已上传资料。
- **FR-02 多模态资料解析**：图片走模型视觉能力、PDF 走文本层抽取、音频走离线转写。
- **FR-15 混合检索**：检索由纯词法升级为「向量语义 + 词法」加权融合。

**验收标准。**

1. 上传后资料出现在知识库列表；就资料内容提问时答案**附带来源条目**。
2. 未命中资料时明确拒绝或走兜底，**不得凭模型常识作答**。
3. 数字文本 PDF 抽取正文入库；扫描件在无侧车时给出**明确提示而非静默空入库**。
4. 音频上传后返回中文转写文本。
5. 向量层不可用时（未装 chromadb / 无 key / 断网 / 报错）**自动回退纯词法**，行为与改造前完全一致。

**边界（主动设计，非缺陷）**：视频解析未实现；不解析网课网页链接（版权风险）。对外材料统一表述为「音频已支持、视频未纳入、网课链接明确不做」。

### 2.2 技术方案

**解析链。** 每种格式有主路径与兜底路径，任一环节缺失都不阻断入库流程：

| 格式 | 主路径 | 兜底 | 落点 |
|---|---|---|---|
| PDF（数字文本） | 文本层抽取 | — | `server/doc_parse.py` |
| PDF（扫描件） | MinerU 侧车 | pypdf + 明确提示 | `server/doc_parse.py` |
| Office | OOXML 解析 | markitdown | `server/office_parse.py`、`markitdown_fallback.py` |
| 图片 | 模型视觉能力 | — | `server/kb_ingest.py` |
| 音频 | 浏览器 Web Audio 解码 → 离线识别 | Vosk | `server/asr.py`、`whisper_cpp.py` |
| Markdown / txt | 分块入库 | — | `server/kb_ingest.py`、`parse_blocks.py` |

**侧车原则。** MinerU、whisper.cpp 一律以 `subprocess` 调用，**不作为 Python 依赖 import 进主进程**。这是「后端零第三方依赖」的核心保障：重型能力缺了只是降级，不会拖垮服务启动。

**音频解码放在浏览器。** 服务器上没有音频处理工具，而浏览器的 Web Audio 自带解码器，mp3 / m4a / webm / ogg / wav 都能直接解——零依赖、零安装。识别引擎采用延迟加载，缺引擎时只让该接口返回中文说明、界面入口置灰，**不影响整个服务启动**。

**混合检索。** `server/retrieval_hybrid.py` 按 `0.6 × 向量相似度 + 0.4 × 词法分` 融合排序：

- 向量通路：`embeddings.py`（单请求 ≤10 条自动分包，缓存键 `sha1(text+model+dim)`）+ `vector_store.py`（Chroma）+ `embed_backfill.py`（历史数据回填）
- 回退条件：`STUDY_LIU_VECTOR=0` / chromadb 缺失 / 任何异常 → 直接返回词法结果
- 联网补题：`web_tools.py`（Tavily），知识库弱命中时可回灌

> **为什么不是一开始就上向量**：改造前的实现根本不是 RAG——命中知识库就把原文整段甩出来（不经过模型），不命中就正常调模型且完全不注入知识库内容；检索是「整句话做子串匹配」，没有分词、打分、排序，这就是「换个说法就查不到」的根因。改造后是真正的「检索 → 过滤 → 注入 → 带引用返回」。

**前端三层结构。** 后端存的是扁平知识点，前端按来源聚合成「笔记 / 文档 / 分块」三层——按来源聚合而非按条目聚合，符合用户对「一份资料」的心智。知识库页提供三档视图：**我的个人库**（`private`，仅自己可见）、**团队共享**（`shared`，全站可见但非官方）、**官方资料库**（`public`，管理员发布的公共资料）；上传时可指定落入哪一档，检索与列表都按档过滤。

**前端落点**：`KnowledgePage.vue`、`ImportPage.vue`、`TranscribePage.vue`、`useKnowledge.js`。

**数据归属。** 知识库内容按账号隔离（见 §5 的数据隔离模型）。

### 2.3 界面与交互

1. 点顶部导航「知识库」进入列表页，左栏笔记、右栏文档详情。
2. 点「导入」上传文件（或直接粘贴文本——`paste_import` 不经 HTTP/multipart，避开 nginx 256k 限制，是演示里最省事的导入路径）。
3. 上传后可看到解析出的分块；可删除整条笔记（删笔记 = 删它名下所有条目，在前端组合即可，后端不用改）。
4. 转写：上传音频文件（**不是**浏览器录音——浏览器录音与语音识别都要求安全上下文，线上 http 环境会被直接拒绝，因此入口形态改为文件选择器，手机端还能直接唤起系统录音机）。
5. 提问时在课程问答页输入问题，答案下方标注引用的资料条目。

**移动端**：知识库页在窄屏下改为上下堆叠，无横向溢出。

## 3. 课程问答闯关

> Hero 卡片原文：围绕当前课程提问，回答会标出参考资料。闯关按题判分，答错记进错题本。

### 3.1 需求

**要解决的问题。** 学完一章，学生既无法验证自己是否真的掌握，也缺少针对性的练习。答错的题目散落各处，不会自动聚合成可复习的集合。

**需求定义（FR-14 / FR-05 / FR-07）。**

- **FR-14 选择题闯关与复盘报告**：按课程与知识库出单选题，难度三档、题数可选，服务端判分并即时讲解，答错进错题本，通关结算并出复盘报告。
- **FR-05 错题管理**：归集错题并支持复习巩固。
- **FR-07 学情个性化指导**：基于练习记录分析薄弱知识点并给出建议。

**验收标准。**

1. 标准答案**只存服务端**，`generate` 响应不带 `answer`——防止前端作弊。
2. 题目逐条校验：`id` 唯一、`stem` 非空、`options` 恰好 4 个、`answer` 恰好 1 个且属于选项 key、`explanation` 非空、`knowledge_point` 非空。校验失败丢弃该题；有效题不足 3 道则报错，不降级。
3. 复盘报告输出得分、正确率、用时、逐题回放与薄弱知识点 Top3，**仅在通关后下发**。
4. 闯关答错自动写入错题本并标注来源 `quiz`。

### 3.2 技术方案

**出题。** `POST /api/quiz/generate`，核心逻辑在 `server/quiz.py`（44 KB）：

- 以课程名作 query 检索私有知识库，命中则作为参考资料，题目标记 `source: "kb"` 且 `retrieved` 带 `id / title / score`
- **弱命中或无结果不再拒绝**，降级为空上下文并基于通用知识严谨出题（`_build_prompt` 的 `material_rule` 约束「基于通用知识严谨出题，不杜撰」），题目标记 `source: "topic"`
- 联网搜索开关：走 Tavily 工具智能体（唯一引入 `langchain-tavily` 的链路，缺依赖时静默回退）

**边出边答。** `GET /api/quiz/stream` 用 SSE 逐题推送，不必等全部题目生成完——这是 3 分钟演示里体验差别最大的一处。

**判分与讲解。** `POST /api/quiz/grade`，服务端判分并即时讲解。答错经 `POST /api/wrongbook/from-quiz` 进错题本，2026-10-11 起**按题型归类**（`server/wrongbook_quiz.py`），便于针对性回练。

**复盘。** `GET /POST /api/quiz/report`，输出得分、正确率、用时、逐题回放与薄弱知识点 Top3。

**前端落点**：`QuizPanel.vue`（难度 / 题数 / 题型选择 + 联网搜索开关）、`ChatPage.vue`（问答与闯关同页）、`ChatPanel.vue`、`WrongBookPage.vue`、`server/wrongbook_quiz.py`。

**依赖闸。** `quiz.py` 受回归闸保护——**不得 import `mysql`**，否则 `tests/run_quiz_regression.py` 的 `quiz_stdlib_only` 检查会变红。MySQL 访问只允许出现在 `server/db.py` 与 `server/storage_*.py`。

### 3.3 界面与交互

1. 进入课程问答页，先提问——回答下方标注引用的资料条目（`retrieved`）。
2. 点「闯关」：选难度（三档）、题数、题型，可开联网搜索。
3. 逐题作答，提交后即时显示对错与讲解；答错的题目标记出来。
4. 全部答完结算，通关后出复盘报告（含薄弱知识点 Top3 与经验结算）。
5. 错题自动进错题本，可在错题本页按课程 / 题型查阅、标记掌握、删除。

**Markdown 渲染**：回答里的 `**` `##` `|` 等标记由自写的零依赖渲染器处理（先整体转义再渲染，链接只放行安全协议），表格和代码块带操作栏——表格可一键复制成可直接粘进 Excel / 飞书表格的格式，也能下载成中文不乱码的 CSV。

## 4. 自习空间

> Hero 卡片原文：进来就展开自习坞。电脑端场景和专注设置左右并排，窄屏上下排列。完整计时结束才计入经验。

### 4.1 需求

**要解决的问题。** 长期独学缺乏正反馈与仪式感，学生容易中途放弃。学习计划再好，没有「坐下来」的那一环也落不了地。

**需求定义（FR-13）。** 提供场景背景、专注计时、环境音混音与纯音乐，配待办、月历备忘、倒数日三个悬浮窗。

**验收标准。**

1. 计时开始才播放当前声音组合，暂停静音，再开始接着响。
2. **完整计时结束才计入经验**——中途放弃不给奖励，避免刷分。
3. 场景只换背景，声音在「专注设置」里叠加。
4. 窄屏（430px 断点）下场景与专注设置上下排列，不横向溢出。

### 4.2 技术方案

**计时与混音。** `useStudyTimer.js`：

- 预设时长 `FOCUS_PRESETS = [5, 10, 15, 25, 50]`（分钟），支持自定义
- 环境音多轨叠加（雨声、咖啡馆等），纯音乐三选一，各自独立音量
- 定时器开始才播当前组合，暂停静音，再开始接着响

**场景。** `SceneBackdrop.vue` 渲染场景视频 / 海报，目录在 `study/catalog.js`。

**三个悬浮窗。** `FloatWin.vue` 为统一外壳，`SpaceLayer.vue` 挂层，`useSpace.js` 管布局：

| 悬浮窗 | 内容 |
|---|---|
| `StudyDock.vue` | 自习坞：场景 + 计时混音 |
| `DateDock.vue` | 月历 + 备忘 + 倒数日（含 `CountdownTimer.vue`） |
| `TodoDock.vue` | 待办 |

**个性化持久化。** 自习设置（场景 / 音乐 / 音量 / 环境声）**按账号分档**存 localStorage（`ownerTag.js` + `useStudyTimer.js`），刷新恢复、登录换档重载；宠物数据同理分档 `zjxt.pet.<用户名|anon>`。这样既保住个性化，又零服务器成本。

**宠物联动。** 自习计时完整结束计入宠物经验（`usePet.js`），Lv5 触发进化。

### 4.3 界面与交互

1. 点顶部导航「自习空间」进入，自习坞自动展开。
2. 电脑端：左侧场景选择，右侧专注设置（时长预设 / 自定义、环境音多轨、纯音乐）。
3. 窄屏：上下排列。
4. 点开始计时 → 声音组合开始播放 → 计时结束计入经验并给宠物加经验。
5. 三个悬浮窗可独立收起 / 展开 / 拖拽。

**移动端修复记录**：手机视口实测曾发现「自习空间是空白页」（正文文字长度实测为 0，其它页 386~1196 字符），已通过最小改动修复；同时解决了悬浮窗竖标签压住正文（内边距仅 8px）与顶部 8 个入口换行成 3 排（吃掉约 140px）两个问题，导航高度由 140px 压到 58px。

> 一处刻意的设计取舍：悬浮窗收起后的竖标签**没有**采用横向滚动方案——因为「更多」菜单是绝对定位的，外层一旦变成滚动容器，下拉菜单会被裁掉。
