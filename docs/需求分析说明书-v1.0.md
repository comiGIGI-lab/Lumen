本说明书回答四件事：用户是谁、要解决什么问题、要做到什么程度算完成、当前做到哪一步。它同时服务三类读者——决赛评委（看需求完整性与验收证据）、开发队友（看实现落点与边界）、后续维护者（看变更记录）。

## 2. 术语

- **LUMEN / 智识有方**：本作品正式名；仓库与代码中仍沿用旧名 `study-liu`。
- **四段式 Agent**：方案生成链路 Planner（拆章节）→ Searcher（找资源）→ Writer（排计划）→ Reviewer（校验），业务层位于 `vendor/study-liu/`。
- **SSE**：Server-Sent Events，`GET /api/plan/stream` 把执行过程实时推给前端，使 Agent 链路从黑盒变白盒。
- **RAG**：检索增强生成；知识库问答先查用户自有资料再交大模型。
- **B30 危机干预**：检测到自伤/求助意图时短路返回 200 并附心理热线，不走常规生成。
- **侧车（sidecar）**：以 `subprocess` 调用的外部二进制（MinerU、whisper.cpp），不作为 Python 依赖 import 进主进程。

## 3. 问题陈述

大学生自学一门新课，通常卡在四个环节：资料散落在课件、PDF 与课堂录音里，无法统一检索；遇到问题无人及时答疑，通用大模型又容易脱离课程材料编造答案；学到哪一步没有客观记录，进度不可控；长期独学缺乏正反馈，中途放弃率高，极端情绪下还缺少恰当的求助通道。

现有工具要么只解决检索（网盘/笔记软件），要么只解决问答（通用 ChatBot），两者不与「这门课、这个学习目标」绑定。本项目要交付的是一个把「资料 → 检索 → 答疑 → 练习 → 反馈」串成闭环的教学智能体，并且全过程可观测、可干预、可降级。

## 4. 目标用户与画像

主用户是在校大学生，覆盖三种典型目标：期末冲刺（2–4 周、以考纲为界）、考研备考（3–6 个月、跨科目）、新课自学（无固定期限、以兴趣驱动）。次用户是教师，用于导入课件快速建课。

系统以结构化画像而非账号资料刻画用户，采集字段为：课程名、当前水平、每日可投入时长、学习目标（期末 / 考研）、截止日期。该组字段落在 `web/src/components/CourseForm.vue`，是方案生成的唯一输入面。

## 5. 使用场景

主旅程为：选择学伴 → 填写课程与画像 → 触发方案生成（四段 Agent 逐节点点亮）→ 浏览大纲/资源/计划三栏 → 勾选已学章节 → 导入课件建知识库 → 基于自有资料提问 → 错题归集与闯关练习 → 导出计划到日历或文档 → 进入自习空间完成当日时长。

三个决定性场景：其一，学生上传 30 页扫描版课件 PDF 后直接问「第三章讲了什么」，答案必须来自该课件而非模型常识；其二，学生口语化提问「那个谁提出的定理来着」，词法检索与向量检索需混合命中；其三，学生在对话中表达极端情绪，系统必须在首轮即给出热线而非继续答疑。

## 7. 功能需求详述

**FR-01 自定义 RAG 知识库。** 用户上传课件、PDF、图片等资料建立个人知识库，问答仅基于已上传资料，并区分考研与期末两类学习目标。验收标准：上传后资料出现在知识库列表；就资料内容提问时答案附带来源条目；未命中资料时明确拒绝或走兜底，不得凭模型常识作答。实现落点：后端 `server/kb_ingest.py`（解析分块入库）、`GET/POST /api/knowledge`（`server/api_server.py` L1193 / L1327）、`POST /api/knowledge/import`（L1247）；前端 `KnowledgePage.vue`（22 KB）、`ImportPage.vue`（17 KB）、`useKnowledge.js`（9.2 KB）。

**FR-02 多模态资料解析。** 图片走 OCR、PDF 走文本层抽取、音频走离线转写。验收标准：数字文本 PDF 抽取正文入库；扫描件在无侧车时给出明确提示而非静默空入库；音频上传后返回中文转写文本。实现落点：`server/doc_parse.py`（PDF 侧车胶水，L8/L93/L121 定义扫描件与 MinerU 回退）、`server/office_parse.py`（OOXML）、`server/asr.py` 与 `server/whisper_cpp.py`（转写）、`POST /api/asr`（L1159 / L1250）；前端 `TranscribePage.vue`（18.6 KB）。边界：视频解析未实现，属 FR-08 未覆盖部分。

**FR-03 知识点结构化可视化。** 将大纲与知识点生成思维导图形态，且支持用户编辑修改。验收标准：按课程生成导图；节点可增删改并进入编辑态；导图与后端 `/api/mindmap` 持久化打通。实现落点：`GET/POST /api/mindmap`（L1164 / L1619）、`MindMapPage.vue`（16.9 KB，文件头注释即为「可编辑思维导图」，L148 新增后直接进入编辑态，L406 自动聚焦编辑框）。

**FR-04 跨对话记忆与用户档案。** 保存历史对话与学习记录，用户无需每次重复输入个人信息。验收标准：历史方案可回看；画像与进度跨会话保持；不同客户端数据互不串扰。实现落点：`/api/me`（L1058）、`/api/accounts`（L1067 / L1288）、`/api/login`（L1257）、`/api/register`（L1271）、`/api/profile`（L1374）、`/api/history`（L1092）；`server/accounts.py`（10.4 KB）；前端 `LoginDialog.vue`（10.5 KB）、`HistoryDialog.vue`、`usePlanHistory.js`。

**FR-05 错题管理。** 归集错题并支持复习巩固。验收标准：闯关答错自动写入错题本并可标注来源 `quiz`；错题可查阅与删除。实现落点：`/api/wrongbook`（L1143 / L1631 / L1654）；前端 `WrongBookPage.vue`（17.3 KB）。

**FR-06 学习目标模板（形态变更）。** 原需求描述为「预设 Prompt 模板，用户填空」。实现形态改为结构化表单：课程名、学习水平、每日时长、目标、截止日期五个字段组合成画像输入，而非填空式模板库。理由是可枚举字段比自由填空更利于后端稳定生成。验收标准：五字段齐备时方案生成成功；改动任一字段产出随之变化。实现落点：`CourseForm.vue`（10.8 KB）、`POST /api/plan`（L1390）。该条与原需求文字存在形态差异，需在答辩口径中主动说明。

**FR-07 学情个性化指导。** 基于练习与学习记录分析薄弱知识点并给出建议。验收标准：通关后复盘报告输出得分、正确率、用时、逐题回放与薄弱知识点 Top3。实现落点：`GET/POST /api/quiz/report`（L1515）、`server/quiz.py`（39.2 KB）。

**FR-08 音视频处理（部分）。** 需求限定「仅支持用户自录内容，不解析网课链接以规避版权」。音频转写已实现（见 FR-02）；视频解析未实现，不做网课链接解析为主动设计而非缺陷。此条在对外材料中应表述为「音频已支持、视频未纳入、网课链接明确不做」。

**FR-09 四段式 Agent 方案生成与过程可视化。** 输入课程与画像，输出大纲、推荐资源、学习计划三栏，并把 Planner→Searcher→Writer→Reviewer 的执行过程实时可视化。验收标准：SSE 推流逐节点点亮并显示真实产出数量；推荐资源链接由资源库程序拼接而非模型生成（防幻觉）。实现落点：`GET /api/plan/stream`（L981）、`POST /api/plan/stream`（L1233）、`stream_pipeline`（L672-742）；前端 `PipelineStepper.vue`（8.7 KB）、`usePlanStream.js`（7.5 KB）、`ResultsGrid.vue`（17.1 KB）。

**FR-10 学伴宠物游戏化机制。** 像素学伴常驻右下角，具备等级、经验、进化、连签与更换能力，提供使用提示与正反馈。验收标准：首访选伴并持久化；使用功能产出经验；Lv5 触发进化；可拖拽与贴边收纳。实现落点：`usePet.js`（14.5 KB）、`PetCompanion.vue`（27.5 KB）、`PetGuide.vue`（8.1 KB）、`PetSprite.vue`（7.6 KB）、`PetProfileDialog.vue`（11.6 KB）、`usePetInteraction.js`（4.8 KB）。

**FR-11 内容安全双层机制 + B30 危机干预。** 硬拦词组与议题名词双层过滤，命中危机意图时短路返回并附热线。验收标准：危险用例被拦截；学术与防护语境被豁免；危机意图返回 200 且附热线，不进入常规生成；改词表须跑回归。实现落点：`server/safety_gate.py`、`safety_rules.py`、`safety_words.py`（合计 27.7 KB）、`server/crisis.py`（17.1 KB）、`detect_crisis`（L349-369）、`log_crisis`（L390-407）、`tests/run_safety_regression.py`。

## 8. 非功能需求

**NFR-01 后端零第三方依赖。** `server/api_server.py`（1,869 行，48 处路由匹配）基于 Python 标准库 `http.server`，第三方能力一律以惰性 import 或侧车子进程引入，缺失即降级。这是本项目最重要的工程约束，也是「1.6 GiB 内存机器仍能演示」的前提。

**NFR-02 链路实时性与可观测。** SSE 推流不可被缓冲；nginx 必须 `proxy_buffering off`，`index.html` 必须 `Cache-Control: no-cache`（否则 Vite 哈希失效导致白屏）。后端 trace 落盘，前端 `TraceDrawer.vue` 可回放。

**NFR-03 降级与回退。** 侧车缺失、无 key、依赖未装、内存不足等任一情况下，功能自动降级且服务照常启动，绝不阻断主链路。扫描件 PDF 在未装 MinerU 时按 `doc_parse.py` L121 明确提示，不静默空入库。

**NFR-04 低资源可运行。** 可用内存 < 2 GiB 时 `mineru.available=false`，不尝试拉取重型侧车。

**NFR-05 并发与限流。** nginx 单 IP 限流已由 30 r/m + burst 10 放宽至 **120 r/m + burst 60**（2026-10-09）。实测：连续 50 次 `/api/health` 全 200 零 429；连续 70 次为 63 次 200 / 7 次 429。终检硬指标为「连续 50 请求无 429」。数据见 `docs\DEPLOY.md` L222–233、L276。

**NFR-06 内容安全与合规。** 详见 FR-11；安全回归套件为改动词表的前置门禁。

## 10. 约束、假设与依赖

约束有三条硬线：后端零第三方依赖基线不得破坏；不得把侧车重型依赖 import 进主进程；Chroma `PersistentClient` 非进程安全，PM2 必须单实例。

假设包括：用户资料规模为单课程量级（数十份文档），不做大规模并发与海量索引优化；评委现场通过公网 IP 访问，不绑域名（ICP 备案周期不允许）。

外部依赖为可缺省项：MinerU（扫描 PDF）、whisper.cpp（转写）、Chroma（向量检索）、Tavily（联网补题）、DeepSeek / 百炼（LLM 与 embedding）。全部缺失时系统仍可完整演示核心链路。

## 11. 已声明边界（不做项）

不解析网课网页链接（版权风险）；不做视频内容解析；不引入完整 LangChain 框架；不建账号体系以外的社交功能；不追求检索规模与并发指标；不在 1.6 GiB 机器上强装重型侧车。
